# Index

Generated by tools/check-modules --write from the module headers. Do not edit by
hand.

Match the task against the "Load when" lines below. Say which module applies,
read it, and follow its steps instead of working them out again. Then read its
overlay, the file in $OVERLAY_DIR with the module's file name, such as
apply-patches.md, if it exists. The overlay wins on conflict. When a step links
to a module from the module's Depends on field, read that module too. $ALIASES
maps the user's short names to modules.

Modules that $MODULES does not enable do not apply. If a step needs one, tell
the user. If a task needs a parameter the profile leaves unset and it has no
default, ask the user. Never guess it.

## Core discipline

How the agent reasons, how much it validates, when it asks, how it waits and how
it handles risky operations.

- [core/evidence-discipline](core/evidence-discipline.md): diagnosing a failure,
  stating a cause, or making a claim about code, data or a past event.
- [core/safe-operations](core/safe-operations.md): running commands that delete,
  overwrite or force anything, working across several repositories, running
  commands as root, writing working files, or touching a publication tree.
- [core/stop-and-ask](core/stop-and-ask.md): a step fails, surprises, or needs a
  choice, and the agent must decide whether to solve the problem or to ask the
  user.
- [core/validation-scope](core/validation-scope.md): planning or running tests,
  reviews or measurements, or deciding when verification is enough.
- [core/waits-and-long-ops](core/waits-and-long-ops.md): starting or waiting on
  builds, test runs, remote jobs, model checks or sub-agents that take more than
  a few seconds.

## Review and build checks

checkpatch, build checks, patchset review and formal model checks.

- [review/formal-model-check](review/formal-model-check.md): `$FORMAL_MODEL` is
  `on` and a patchset adds or changes a protocol in which two or more concurrent
  contexts coordinate through shared state, or the user asks for a TLA+ model, a
  TLC run or a herd7 litmus test.

## Debugging

Crash analysis, bug report triage and event tracing.

- [debug/bug-report-triage](debug/bug-report-triage.md): a task investigates a
  reported kernel issue, such as a mailing-list bug report, a CI or bot finding,
  a user complaint or a batch of AI-generated findings, even when nobody calls
  it triage.
- [debug/event-tracing](debug/event-tracing.md): adding kprobes, bpftrace
  scripts, debug probe stubs or an in-kernel trace ring to see what the kernel
  does, including hunting a rare event in a high-rate stream where the history
  before the event matters.
